# Implementation Plan: Import Versions — Plot-as-Resource Addendum

**Branch**: `046-import-outline-versions` | **Date**: 2026-04-24 | **Spec**: [spec.md](./spec.md)

## Summary

This plan covers two targeted changes to the modern import parser and its preview UI,
building on the already-implemented import-version-selection infrastructure:

1. **Plot warning fix**: Stop warning when a plot heading (H4) lacks the `|` prefix.
   Both `headingLevel === PLOT_HEADING_SIZE` and `text.startsWith("|")` are equally valid
   plot signals; a warning should only fire when a plot title cannot be extracted.

2. **Plots as a separate resource**: The modern parser emits `plots: ImportPlot[]` on
   `ImportParseResult` instead of folding plots into `tags`. Scenes gain a `plotIds` field.
   The preview modal pre-seeds `customizations.plots` from the response, so parser-identified
   plots appear immediately on the Plots tab without requiring manual "Convert to plot" toggles.
   The legacy "tag → plot conversion" toggle in the Tags tab is unchanged.

## Implementation Phases

### Phase A — Backend Types & Parser

**Files**: `express/src/types/importOutline.ts`, `express/src/services/importOutlineModernParser.ts`

#### A1 — Add `ImportPlot` type; extend `SceneElement` and `ImportParseResult`

```ts
// New type
export type ImportPlot = {
  id: string;
  name: string;
  color: string | null;
};

// SceneElement gains:
plotIds: string[];

// ImportParseResult gains:
plots: ImportPlot[];
```

#### A2 — Fix plot warning in modern parser

In the `headingLevel === PLOT_HEADING_SIZE` branch, **remove** the
`if (!headingText.startsWith("|")) { warn + skip }` guard.
Always strip the `|` prefix if present and extract the title. Warn only if `plotTitle` is empty.

#### A3 — Introduce `ensurePlot` helper and `plotMap`

Add `const plotMap = new Map<string, ImportPlot>()` to the parser.
Add `ensurePlot(result, plotMap, name, color)` mirroring `ensureTag`, writing to `result.plots`.
Replace all `ensureTag(... plotTitle ...)` calls in the plot-heading and paragraph-fallback
branches with `ensurePlot(...)`.

#### A4 — Rename `pendingPlotTagId` → `pendingPlotId`; assign to `scene.plotIds`

The scene branch pushes `pendingPlotId` into `scene.plotIds` (not `scene.tagIds`).
The legacy `pendingPlotTagId` variable is removed entirely.

#### A5 — Backend build validation

`cd express && npm run build` must exit 0.

### Phase C — Preview Modal Seeding

**File**: `web/src/components/dashboard/ImportOutlineModal.tsx`

#### C1 — Seed `customizations.plots` from `result.plots`

In `handlePreview`, replace the static `plots: [{ ...DEFAULT_MAIN_PLOT }]` init with:

```ts
const parserPlots: ImportPlotCustomization[] = (result.plots ?? []).map(
  (p, idx) => ({
    id: p.id,
    name: p.name,
    color: p.color ?? DEFAULT_PALETTE_COLORS[idx % DEFAULT_PALETTE_COLORS.length] ?? "#729cfd",
    isDefaultPlot: false,
    ignored: false,
  }),
);
setCustomizations({
  ignoredCharacterIds: [],
  characterMerges: {},
  plots: [{ ...DEFAULT_MAIN_PLOT }, ...parserPlots],
});
```

Empty `result.plots` collapses to `[DEFAULT_MAIN_PLOT]` — legacy path unchanged.

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Legacy imports accidentally receive `plotIds` | Low | Only modern parser creates plots; legacy parser unchanged |
| `customizations.plots` seeding duplicates main plot | Low | Seed always starts with `DEFAULT_MAIN_PLOT` then appends parser plots |
| Elements tab crashes on missing `plots` prop | Low | Prop defaults to `[]`; `plotIds` is optional on scene type |
| Tag-to-plot toggle conflicts with pre-seeded plots | None | `tag_N` and `plot_N` IDs never collide |
