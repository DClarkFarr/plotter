# Implementation Plan: Import Name Standardization

**Branch**: `049-normalize-import-names` | **Date**: 2026-04-24 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/049-normalize-import-names/spec.md`

## Summary

Standardize imported character and tag names so case-only variants resolve to one canonical stored value, while preserving readable display text and exposing consolidation outcomes in import feedback. The implementation will centralize canonicalization in shared import normalization utilities, apply it consistently in modern parsing and DB creation/matching, and return a normalization report in import results.

## Technical Context

**Language/Version**: TypeScript 5.9 (Node.js backend, React frontend)
**Primary Dependencies**: Express, MongoDB driver, officeparser, TanStack Query/Router, Flowbite React
**Storage**: MongoDB (`tags`, `characters`, `scenes`, `stories` via import workflow)
**Testing**: Manual import preview/create validation plus `npm run build` in `express/` and `web/`
**Target Platform**: Browser + Node.js API service
**Project Type**: Monorepo web app (`express/` + `web/`)
**Performance Goals**: Keep import parsing and create flow aligned with existing behavior; no material increase in import latency for common files
**Constraints**: Preserve current import modes (`legacy` and `modern`), maintain backward-compatible API fields where possible, avoid duplicate tag/character creation from case-only differences
**Scale/Scope**: Import pipeline and related response/types only (no schema migration)
